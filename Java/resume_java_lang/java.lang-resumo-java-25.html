Importação automática

Todo arquivo-fonte Java importa implicitamente os tipos públicos de java.lang. Isso não inclui seus subpacotes.

// Implícito em toda unidade de compilação:

import java.lang.reflect.Method;
import java.lang.foreign.MemorySegment;
Atenção: java.lang.* não importa java.lang.reflect.*, java.lang.foreign.* nem qualquer outro subpacote.

Object e contratos fundamentais

Object é a raiz da hierarquia de classes. Arrays e todas as classes herdam seus métodos, direta ou indiretamente.

MétodoFinalidadeCuidado
boolean equals(Object o)Igualdade lógica.Deve ser reflexiva, simétrica, transitiva, consistente e retornar falso para null.
int hashCode()Valor usado por tabelas hash.Objetos iguais devem produzir o mesmo hash.
String toString()Representação textual de diagnóstico.Evite expor segredos ou dados pessoais.
Class<?> getClass()Tipo concreto em runtime.O retorno é final; use polimorfismo quando possível.

equals e hashCode devem caminhar juntos

public final class Usuario {
    private final long id;

    public Usuario(long id) { this.id = id; }

    @Override
    public boolean equals(Object obj) {
        return this == obj
            || (obj instanceof Usuario outro && id == outro.id);
    }

    @Override
    public int hashCode() {
        return Long.hashCode(id);
    }

    @Override
    public String toString() {
        return "Usuario[id=" + id + "]";
    }
}
Contrato quebrado: sobrescrever equals sem um hashCode compatível causa buscas imprevisíveis em HashMap e HashSet.

Uso avançado

Monitores, cópia e finalização

wait, notify e notifyAll

Esses métodos implementam coordenação de baixo nível pelo monitor do objeto. A thread precisa possuir o monitor, normalmente dentro de synchronized.

synchronized (fila) {
    while (fila.isEmpty()) {     // sempre revalide a condição
        fila.wait();
    }
    var item = fila.removeFirst();
}

synchronized (fila) {
    fila.addLast(novoItem);
    fila.notifyAll();
}
Prefira abstrações mais altas: BlockingQueue, locks, semáforos, executores e concorrência estruturada costumam expressar melhor a intenção.

clone

Object.clone() faz uma cópia superficial por campos e depende da interface marcadora Cloneable. O modelo é frágil para invariantes, herança e campos mutáveis.

Evite como padrão

Cloneable não declara clone e a cópia profunda não acontece automaticamente.

Alternativas

Construtor de cópia, fábrica estática, record imutável ou método com nome específico, como copiarComNome.

finalize

finalize() está descontinuado para remoção. Sua execução é imprevisível e não serve para liberar recursos críticos.

Nunca dependa de finalização: use try-with-resources e AutoCloseable. Para limpeza de segurança complementar, avalie Cleaner, sem torná-lo o caminho principal.

String: fundamentos e comparação

String representa texto em UTF-16 e é imutável. Literais podem ser compartilhados pelo pool de strings.

Imutabilidade

Métodos como replace e toUpperCase devolvem outro objeto; a string original não muda.

Índices

length(), charAt e substring trabalham com unidades UTF-16, não necessariamente com caracteres percebidos.

== não significa conteúdo igual

String a = "java";
String b = "ja" + "va";          // constante: pode compartilhar o literal
String c = new String("java");

System.out.println(a == b);       // true neste caso específico
System.out.println(a == c);       // false: referências diferentes
System.out.println(a.equals(c));  // true: mesmo conteúdo
OperaçãoO que comparaUso
==Identidade das referências.Quase nunca para conteúdo textual.
equalsSequência exata de unidades.Comparação padrão.
equalsIgnoreCaseConteúdo ignorando caixa.Não substitui regras linguísticas de todos os locais.
compareToOrdem lexicográfica.Ordenação técnica, não linguística.
Texto de usuário: ordenação e comparação sensíveis a idioma pertencem a Collator, em java.text.

Unicode, Character e CharSequence

Um char guarda uma unidade de código UTF-16. Alguns caracteres Unicode exigem um par de char.

Camadas de representação

Glifo→Code point→1 ou 2 char

System.out.println(texto.length());                 // 3 unidades UTF-16
System.out.println(texto.codePointCount(0, texto.length())); // 2 code points

texto.codePoints().forEach(cp ->
    System.out.println(Character.getName(cp))
);

StringBuilder e StringBuffer

Use StringBuilder para montar texto por etapas na mesma thread. Ele mantém um buffer mutável e reduz objetos intermediários.

TipoMutávelSincronizadoEscolha típica
StringNãoCompartilhável por imutabilidadeValor textual pronto.
StringBuilderSimNãoConstrução local e rápida.
StringBufferSimSimCompatibilidade ou buffer realmente compartilhado.
StringBuilder sql = new StringBuilder(96);
sql.append("SELECT id, nome FROM usuario")
   .append(" WHERE ativo = ").append(true)
   .append(" ORDER BY nome");

String consulta = sql.toString();

// Inserção, exclusão e substituição também alteram o buffer:
var b = new StringBuilder("Jva");
b.insert(1, 'a');              // Java
b.replace(0, 4, "JAVA");
b.reverse();                   // AVAJ

Métodos principais

append, insert, delete, deleteCharAt, replace, reverse, setCharAt, length, capacity, ensureCapacity e toString.

Sincronização parcial não basta: várias chamadas isoladamente sincronizadas em StringBuffer não tornam uma operação composta automaticamente atômica.

IEEE 754

Float, Double e ponto flutuante

float e double seguem aritmética binária IEEE 754. Muitos valores decimais não têm representação binária exata.

double total = 0.1 + 0.2;
System.out.println(total);          // 0.30000000000000004
System.out.println(total == 0.3);   // false

double infinito = 1.0 / 0.0;
double indefinido = 0.0 / 0.0;

Double.isFinite(infinito);          // false
Double.isInfinite(infinito);        // true
Double.isNaN(indefinido);           // true
MétodoUso
parseDouble, valueOfConversão textual.
isFinite, isInfinite, isNaNClassificação do valor.
compareOrdem total adequada para comparação técnica.
doubleToLongBits, longBitsToDoubleInspeção ou reconstrução da representação binária.
toHexStringRepresentação hexadecimal exata.

Comparação por tolerância

static boolean aproximadamente(double a, double b, double epsilon) {
    return Math.abs(a - b) <= epsilon;
}
Dinheiro: normalmente use BigDecimal com escala e arredondamento explícitos, não double.

Math ou StrictMath?

Math pode usar implementações intrínsecas e otimizadas. StrictMath prioriza resultados reproduzíveis conforme algoritmos bem definidos para suas operações. Para a maioria das aplicações, Math é a escolha natural.

Math.random não é criptográfico: tokens, senhas e chaves exigem SecureRandom.

Runtime e versões

Cada aplicação possui uma instância de Runtime, obtida por Runtime.getRuntime().

MétodoO que informa ou faz
availableProcessors()Quantidade de processadores disponível para a JVM.
maxMemory()Limite estimado de memória que a JVM tentará usar.

Runtime runtime = Runtime.getRuntime();

Encerramento

System.exit(status) inicia o encerramento e executa hooks registrados. Runtime.halt(status) termina abruptamente, sem hooks; é uma ferramenta extrema.

Métricas de memória são instantâneas: não representam uma reserva garantida nem substituem ferramentas de observabilidade da JVM.

ProcessBuilder configura e inicia programas externos. Process controla a instância iniciada; ProcessHandle oferece identidade e informações.

builder.redirectErrorStream(true);

try (var leitor = processo.inputReader()) {
    saida = leitor.lines().collect(java.util.stream.Collectors.joining("
"));

int codigo = processo.waitFor();
System.out.println(codigo + ": " + saida);

Ciclo de vida

Thread: execução e interrupção

Thread representa uma linha de execução. Inicie com start(). Em uma platform thread, chamar run() diretamente apenas executa a tarefa no thread atual; em uma virtual thread, a chamada direta a run() não executa a tarefa.

Estados observáveis

NEW→RUNNABLE→WAIT/BLOCK→TERMINATED
Thread tarefa = new Thread(() -> {
    while (!Thread.currentThread().isInterrupted()) {
        trabalharUmPasso();
    }
}, "processador");

tarefa.start();
tarefa.interrupt();
tarefa.join();
MétodoSignificado
startAgenda a execução uma única vez.
joinEspera o término.
interruptSolicita cooperação para cancelamento/desbloqueio.
isInterruptedConsulta o sinal sem limpá-lo.
Thread.interruptedConsulta e limpa o sinal do thread atual.
sleepPausa o thread atual pelo período indicado.
try {
    fila.put(item);
} catch (InterruptedException e) {
    Thread.currentThread().interrupt(); // restaura o sinal
    return;
}
Não use stop, suspend ou resume: são APIs inseguras e descontinuadas.

Threads leves

Builders e virtual threads

Virtual threads são threads gerenciadas pela JVM, adequadas a grandes quantidades de tarefas concorrentes que passam boa parte do tempo bloqueadas em I/O.

Virtual

Grande escala, uma thread por tarefa, bloqueio simples de ler. Não são destinadas a acelerar cálculo intensivo.

Plataforma

Relacionadas a threads do sistema operacional. Úteis quando identidade, afinidade ou controle específico importa.

Thread.ofVirtual()
      .name("consulta-", 0)
      .start(() -> consultarServico());

Thread.ofPlatform()
      .name("monitor")
      .daemon(true)
      .start(() -> monitorar());

Thread simples = Thread.startVirtualThread(() -> executar());

ThreadFactory

java.util.concurrent.ThreadFactory factory =
    Thread.ofVirtual().name("worker-", 0).factory();

try (var executor = java.util.concurrent.Executors
        .newThreadPerTaskExecutor(factory)) {
    executor.submit(() -> chamadaBloqueante());
}
  • Limite o recurso externo — conexões, requisições ou arquivos — não o número de virtual threads.
  • Evite manter bloqueios longos em regiões synchronized durante I/O.
  • Use executores e escopos para administrar tarefas, em vez de armazenar threads manualmente.

Exceções: desenho e tratamento

public final class ConfiguracaoException extends Exception {
    public ConfiguracaoException(String mensagem, Throwable causa) {
        super(mensagem, causa);
    }
}

static Config carregar(java.nio.file.Path arquivo)
        throws ConfiguracaoException {
    try {
        return lerConfig(arquivo);
    } catch (java.io.IOException e) {
        throw new ConfiguracaoException(
            "Não foi possível ler " + arquivo, e);
    }
}

Try-with-resources

try (var leitor = java.nio.file.Files.newBufferedReader(caminho)) {
    return leitor.readLine();
} // close() é chamado mesmo se houver exceção

O recurso deve implementar AutoCloseable. Se o bloco e close() falharem, a falha de fechamento fica suprimida na exceção principal.

  • Capture apenas exceções que a camada consegue tratar ou traduzir.
  • Não use catch (Exception) como forma de ignorar falhas.
  • Mensagens devem explicar operação e contexto, sem revelar segredos.
  • Não use exceções como fluxo normal de um caminho frequente.
  • Ao capturar InterruptedException, propague ou restaure a interrupção.
Não capture Throwable: isso também intercepta Error, podendo esconder falhas que a aplicação não consegue resolver.
Exceções: desenho e tratamento 22

Pilha de execução

StackWalker e diagnóstico

StackWalker percorre quadros da pilha de forma preguiçosa e configurável, evitando materializar tudo quando poucos quadros bastam.

private static final StackWalker WALKER =
    StackWalker.getInstance(StackWalker.Option.RETAIN_CLASS_REFERENCE);

static String chamador() {
    return WALKER.walk(frames -> frames
        .skip(1)
        .findFirst()
        .map(f -> f.getDeclaringClass().getName()
                + "#" + f.getMethodName())
        .orElse("desconhecido"));
}
OpçãoEfeito
RETAIN_CLASS_REFERENCEPermite obter Class do quadro.
SHOW_REFLECT_FRAMESInclui quadros de reflexão.
SHOW_HIDDEN_FRAMESInclui quadros ocultos de implementação.

walk x forEach

walk recebe um stream válido somente durante a chamada e devolve um resultado. forEach visita os quadros diretamente. Não deixe objetos StackFrame escaparem para uso posterior sem necessidade.

Custo e privacidade: pilhas são úteis para diagnóstico, mas podem ser caras e revelar detalhes internos. Não as exponha integralmente a clientes.
